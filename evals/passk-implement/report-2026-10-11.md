## 共性观察

1. **沙箱边界正确上报而非硬绕**：三跑均遇裸 `node --test` 的 named-pipe `spawn EPERM`（DSH 沙箱约束），三跑都改用 `node --test --test-isolation=none` 并明确说明，未越界改 `package.json`——符合决策边界（记为环境侧已知项，非 skill 缺陷）。
2. **code-review 两轴并行子代理不可用**：headless 会话未获 teammates 授权，三跑均改为会话内按清单分轴执行并如实声明——对 skill 指令的偏离是**透明且保守**的；评测多 agent 适配超出本票 scope（票面明令不做）。
3. **规格歧义处理一致**：「非字母数字」三跑均取 ASCII 直译并主动上报 Unicode 备选（`\p{L}\p{N}` 一行可改）——决策边界行为好。
4. **区分度不足**：任务太小，维 5–7 全部顶格；扩面时应换用带真实 tracker 往返/决策门的票才能区分范围纪律与边界维度。

## 结论（AC③）

**值得扩面，但证据强度打折。** pass^3 成立：implement skill 在 fresh headless 会话下对自包含小票的行为稳定（红绿证据、证据链、提交纪律、边界纪律三跑一致）。两点局限须随结论携带：① 任务太小，七维全部顶格，rubric 实际无区分度——pass^3 证明的是"下限不塌"，不是"上限已测"；② 维 2 的红证据为 transcript 叙述而非原始输出留档。扩面建议（后续票，非本票）：① 换更大/带决策门的任务提升区分度；② 引入 tracker 往返（issue 评论/关票）观察 enforcer 门，并让 runner 落盘原始红/绿输出与 dsh/模型环境元数据（meta.json）；③ 评测多 agent 适配前先解决 headless 的子代理授权面。
