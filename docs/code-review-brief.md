# 复核 brief（/code-review 专用）

**谁读**：审阅阶段（`/code-review` 的两个轴 subagent）。实现阶段不必读——实现 agent 的
上下文压力最大，标准不该压给它；审阅 agent 拿到 diff，没有探索成本，由它承担标准。

**入口**：`/code-review` 技能；本文只定"本仓怎么组装那两份 brief"。

## 1. 定固定点

- 默认固定点 = **`HEAD`**（起手快照）。
- 工作还没提交：先 `git add -A`，再用 `git diff --staged`——否则**新增文件不出现**在 diff 里
  （本次 #55 有 4 个新增文件，漏掉就等于审了个残缺面）。
- **复核后必须重新 `git add -A` 再 commit**：index 是"复核前"的快照，复核产生的修改只落在工作树，
  而 pre-commit 的 verify-all 跑的是**工作树**——它会为提交里根本没有的内容背书。`#82` 实测：
  提交记 `283/30`、树里是 `347/32`，只有事后 `git status` 才发现，靠两次 amend 补救。
  `.githooks/pre-commit` 现在会**响亮拒绝**这种脱节（`tests/verify-precommit-hook.mjs` H1）。
- 已提交：`git diff <fixed-point>...HEAD`（三点，对 merge-base）。
- 先验固定点可解析、diff 非空，再派 subagent——坏 ref 要在这一层炸，不要炸在两个 subagent 里。

## 2. 定 spec 源

1. 提交信息里的票号 → `gh issue view <NN> --repo ch1bug/dsh-matt-preset`（当前票 = 提交信息首个 `#NN`）；
2. 否则问 human 要 spec；
3. 都没有 → Spec 轴跳过并明说"无 spec"，不要猜 AC。
4. **票面 AC 之间是否互斥（算术可行性）**：AC 一边要求"压到 X"、一边要求"某块一字不动"时，
   先算一遍能不能同时成立（#56：七门 verbatim 已占 10%，与 "~1/3" 不可兼得）。冲突须显式
   上报：要么回票面改口径，要么实现方记录取的口径并请 human 裁决——不得静默选一个 AC 满足。
5. **票面的「现象 / 根因 / 实测」段是可证伪断言——先实测再判 AC**：对 HEAD 跑一遍票面描述的
   输入，再决定 AC 怎么算满足。票面与实际不符时**报告口径修正**并写进交付记录（ADR / 票面
   评论），不要静默按票面文字实现。#66 实测：票面称"`prefix` 以 `/` 结尾的目录通配可用"，
   而 HEAD 上 `dir/*`、`dir/name-*.txt`、`a*.mjs` **全部恒空**，AC2 因此建在错误前提上。
6. **新增的每条断言都要证明非空洞**（不只是"守卫"——隔离 / 清理这类辅助环同样算）：把被断言的输入换成
   反例（回退实现用 `git show HEAD:<file>` 到临时副本，手法与陷阱见
   [dev-environment §0.2](dev-environment.md)），用例必须**红**；说不出"什么输入能让它红"就是同义反复
   （负债）。#66 实例：回退 `lib/payload.mjs` 后 P4/P6/P7/P9/P10 全红，P10 复现票面症状
   （`exit=0`、store 少发）。#75 实例：`--port 0` 下"分到的端口不是保留口"**恒真**（复核才抓到），改为
   保留口前后占用快照才可红；**扰动要打在运行时真正读的那份上**（生成载体，不是源文件）。
   **三条硬约束（#82 会话踩过全部三条）**：① 扰动前先自检 **needle 命中数 > 0**
   （`$src.Contains()` / `grep -c`）——0 命中是**假证据**，不是"没漂移"（本次一条文档探针静默 0 命中，
   差点把"守卫有效"当结论）；② 回退用 `git show HEAD:<file>` 写临时副本
   （`git stash push` 会重置 index 并按 autocrlf 改行尾），回退后**编辑前重新 `read`**
   （FS 版本守卫报 `file changed since it was read`，本次白读两次）；③ 探针里拼 `\n` 会撞 CRLF
   工作树（`-Raw` 读进的是 `\r\n`）——按 `\r?\n` 切分或用显式 `$nl`，否则替换静默不生效。
   **实验标记（2026-10-17 起，机械拦）**：调试/扰动探针一律带唯一前缀 —— `[DEBUG-<唯一串>]` /
   `[MUTATION-<唯一串>]`，提交前必须清掉。理由：**标记死了才叫实验**，留下的标记意味着"被跑过的
   那棵树"与提交物不是同一份（而 verify-all 照样绿）。`.githooks/pre-commit` 已机械拦 staged 的
   `tests/*` **新增行**（`grep -E '^\+.*\[(DEBUG|MUTATION)-'`，只看 tests/：文档里叙述这套做法不算）；
   判据由 `tests/verify-precommit-hook.mjs` H5/H6 钉住。
7. **复核改动面用 `git diff`，不要重读全文**：review 阶段要确认"某文件改成了什么样"时，
   取 `git diff <base> -- <file>`（或 `git diff --stat` 先看形状）——**整读只在 diff 不足以判断时才做**。
   #71 实测：`read` 19 次共 **156,720 字符**，其中一半是`workflow-enforcer.mjs` 与
   `tests/verify-enforcer.mjs` **各整读 4 次**（侦察一次是必要的，改动后复核又整读一次是白烧；
   两个文件累计 103,898 字符）。本仓的实现改动**常是纯追加**（#71 的 `workflow-enforcer.mjs`
   最终 `323 插入 / 0 删除`），此时 diff 就是改动面本身，全文一个字都不必再进上下文。
   **复读不是免费的**：`read` 默认不带 `limit`，一次整读就是全量进窗口。

### 3.1 本仓的"失败"长什么样（各面）

审阅前先读这一节：它把"这仓库里什么叫坏"说在前面，比事后从 smell 基线里推断便宜。
（口径来源：Anthropic Claude Code 团队的 `REVIEW.md` 实践——*明确该仓库中"失败"长什么样*，
[原文](https://claude.dev/blog/solving-code-review-at-anthropic/)；本文按本仓载体落地。）

| 面 | 失败形态（= 该报的） |
| --- | --- |
| **断言** | 断言**自己写错了预期**而不自知：绿灯只证明"代码符合断言"，不证明"断言符合语义"。#71 实测：94 条全绿时，「聚合每批至多一次」仍失效（3 个 session 各聚合一次）——靠 Spec 轴新造夹具才抓到。 |
| **守卫** | **空转**：断言恒真（说不出什么输入能让它红）、或扰动**没打在被读的那份上**（假绿）。#71 实测：头注配方照做只得假绿（`preset-harness` 硬编插件路径）→ 已立 `tests/verify-perturbation-recipe.mjs` P1–P6 钉住。 |
| **文档** | **说谎**（不是"写得不好"）：文档描述的行为与代码不符，或引用了被改行为的旧口径。已登记的同类：#66（口径漂移落在 diff 之外）、#71（`docs/batch-state.md` 写"由 `retro:` 抑制"，而代码当时做不到）。 |
| **配置 / 载体** | **路由错**：生成载体与源脱节（`agent.cordis.yml` ↔ `cordis.patch.yml`，`scripts/regen-bundle.mjs`）、基线 fixture 未随正文重取（AC1/S3/M4 红）。 |
| **基线 / 快照** | **漂移**：冻结基线（`tests/fixtures/*-v1.txt`）与当前正文不一致。**注意区分**：随文本政策**有意重取**不是漂移（D48 先例），漏重取才是。 |
| **测试卫生** | **泄漏**：临时目录 / 夹具没清（#77 是既有票）；探针残骸留在 `tests/`（会被 `verify-all` 当用例扫，读数分母漂）。 |

### 3.2 挑刺设限（哪些**不报**）

设限是为了让信号可读：报告越长，真缺陷越容易被淹没。以下**一律不报**：

- **工具已强制的**：格式、行尾、import 顺序、privacy denylist 命中——`verify-all` / pre-commit 已经拦。
- **存量风格，且本票没碰**：本仓的 smell 基线是**判断项**；若命中的代码既非本次 diff 引入、也非本次改动
  直接相关，**不报**。#71 实测：Standards 轴报了 `Primitive Obsession`（`retroPush`/`batchDeclared` 两个
  WeakMap），而它与既有 `ticketClosed`/`batchClose` **同构**、属存量风格——该轴自己判了"不建议本票改"，
  这是正确处置，但仍花了篇幅。下次直接略过，或一句话归入"存量，另立票"。
- **本票范围外的改进建议**：Out of scope 明写的东西（#71 的"拦截 push"、"自动落地候选"）不报。
- **没有文件名 + 行号证据的猜测**：`REVIEW.md` 口径——**必须给具体文件名和行号，不是根据命名猜测**。
  说不出位置就说明还没定位，不该进报告。
- **纯文风偏好**：措辞、命名品味，除非该命名造成歧义（Mysterious Name 的判据是"看不出做什么"，
  不是"我不喜欢"）。

**判断项与硬违规必须分开标注**：硬违规 = 违反上面某一节写下的标准（指名文件 + 规则）；
判断项 = smell 基线或本节的"失败形态"推断。**本仓文档化标准永远压过基线。**

## 4. smell 基线

从 `code-review` 技能正文取（Fowler *Refactoring* ch.3 的 12 条），**整段粘进 subagent prompt**——
subagent 没有你的上下文（不会自带基线）。别复述成一句话摘要，摘要会让基线失效。

## 5. 两轴 brief 模板

两个 subagent **同时**发（一条消息两个调用），各给"diff 命令 + 提交列表 + 该轴材料 + 它的 brief"：

- **两轴都要真跑被测用例**：reviewer 收到 diff、没有探索成本，正是该自己确认"这条断言非空洞"的一轴。
  `node tests/<file>.mjs`。依赖接线锚在 **`tests/node_modules/`**（`@deepseek-ai` junction → 本机 dsh
  安装；一条 `node scripts/link-runtime-deps.mjs` 补齐，D43）——仓根 `node_modules` 只有 `yaml`，
  **别据此判"套件跑不了"**（#82 会话的 Standards 轴就这么退化成只读码，4 条发现里 2 条本可自证）。

- **Standards 轴**：diff 命令 + 第 3 节清单 + **§3.1「失败长什么样」+ §3.2「挑刺设限」** +
  粘好的 smell 基线 + **§8 缺陷类登记表**（本仓栽过的类，优先搜）+ 要求
  "逐文件/逐 hunk 报：违反哪条文档化标准（指名文件 + 规则）；命中哪条 smell（引用 hunk）；
  区分硬违规与判断项；工具已强制的跳过；**§3.2 列明的不报项一律不报**；<400 词"。
  （§3.1/§3.2 是**本仓的** `REVIEW.md` 等价物：前者说"这仓库里什么叫坏"，后者说"哪些不报"。
  两者都要**整段粘进 prompt**——subagent 没有你的上下文。）
- **Spec 轴**：diff 命令 + spec 原文 + **§8 缺陷类登记表** + 要求
  "(a) 缺失或只实现了一半的需求；(b) 票面没要求的行为（scope creep）；(c) 看似实现实则错的地方；
  每条引用 spec 原文；<400 词"。

### 复核者的写权限 = 无（**整段粘进两轴 brief**）

> **这一段与 §3.1/§3.2/§4 同性质：不是给你读的说明，是给 subagent 的正文。** 照抄进两轴 prompt。
> 别复述成一句话摘要——摘要会让约束失效（subagent 没有你的上下文，也没有你的记忆）。
> **⚠ 给你（派单者）的一句话**：本节是**本仓唯一**能把写权禁令送达复核者的通道，而**守卫守不住它**
> （§末"边界"说明：换体裁架空整节，10/10 实测绕过）。**"先提交再复核"才是主防线**——它不是备选项。
> 为什么写在这里而不靠派单者记得（#113 事故，非假想）：复核子代理用 `git checkout` 把
> **尚未提交**的 `workflow-enforcer.mjs`（part C 全部 171 行）还原成 HEAD → 套件 `SyntaxError`
> 崩溃；`.scratch/perturb113/`（当时**唯一**的恢复副本）**也被清掉**；AC4/AC5/AC6 证据全部作废。
> Standards 轴当时的收尾语逐字为 "the perturbation was reverted via `git checkout`"——它不觉得自己
> 做错了，因为**没有任何一处写下来告诉它不许**。约束只活在派单者的记忆与逐跳传递的 handoff 里。

**前置：冻结基线（首选做法，不是可选项）**

- **先提交再复核**为首选：fixed point 成为一个**已存在、不再变动的 commit**，"复核期间树在动"这个
  根本问题**从此消失**——这是结构性根治，比任何禁令都强。本仓 #48 会话实测即如此（先提交，
  两轴均守住）。
- 做不到（实现尚未成形、非提交不可）时，**显式告知复核者"这是移动靶，只读快照"**，
  并在报告里把基线漂移当作已知前提。**默认假设永远是"树已冻结"**——不声明就等于声明了冻结。

**禁令（逐条，无例外）**

- **禁止任何 `git` 写命令**：`git checkout` / `git restore` / `git stash` / `git clean` /
  `git reset` / `git add` / `git commit` / `git am` / `git apply`。**这不是"尽量别用"**：
  这台工作树是多会话共用的，你眼里"干净的工作树"就是实现者**未提交的全部工作**。
- **禁止删改仓内任何文件**，**包括 `.scratch/`**。当次事故的第二半正是这个：`.scratch/perturb113/`
  是**唯一**的恢复副本，被顺手清掉后连人工恢复的路都断了。`.scratch/` 是 gitignore 的运行时面，
  但它装的是**证据**——未跟踪 ≠ 可丢弃。
- **需要临时文件一律落 `os.tmpdir()`**（Node `mkdtempSync(join(tmpdir(), …))`），**不得落仓内**。
  落仓内会与实现者的工作树互相踩，且可能被 `verify-all` 的 `tests/*.mjs` 扫描当用例跑（§3.1 测试卫生）。
- **要验证"回退某文件后会不会红"，只允许在临时目录的镜像副本上做，永不碰真树**：
  复制那份文件到 `os.tmpdir()`、在**副本**上扰动、对副本取证。真树**自始至终是只读的**，
  **不允许**对它做任何回退或还原。（回退手法本身——为什么不用 `git checkout --` 还原——见
  **#108**，两票边界互补。）
- **报告里若写了"我恢复了工作树"，那就已经违规了**：复核者**从不**需要恢复任何东西——
  真树本来就是只读的，没有任何东西该被改动。#113 的 Standards 轴正是用这句话作为收尾语的。

**这条约束的边界（别把它读成"已经被守住了"）**：它**不可能**靠机械守卫证明"你真的粘进去了"——
判决权在你（派单者）手里。守卫（`tests/verify-review-brief-readonly.mjs`）只保证三件事：
这段文本**在仓里**、处于**禁令语气**、且**未在已枚举的几种体裁下自我作废**。
**它守不住"换个体裁把整节架空"**——独立对抗验证实测：十种新体裁（例外条款 / 时间限定 /
主体错位 / 反事实 / 引述他人 / 优先级声明 / 范围切割 / 元层声明 / 宣布由他节取代 / 授权式）
**全部 10/10 绕过**（exit=0 全绿，禁令词面一个不少）。这是开放集，加正则永远追不完
（正是 #79 废掉子串匹配的理由），故**显式声明不覆盖**（守卫 R7）而非继续加宽。

**真正的防线按强度排序**：① **基线冻结「先提交再复核」**——结构性根治，fixed point 不再变动，
"复核期间树在动"这个问题**消失**，与禁令写得多严无关（这才是主防线）；
② **把本节整段粘进两轴 prompt**（照 §3.1/§3.2/§4 的做法），文本送达才算数；
③ **你读报告时把"我恢复了工作树"当违规处理**——#113 的收尾语正是这句话。

## 6. 出报告

两轴**分开**呈现（`## Standards` / `## Spec`），**不合并、不重排、不跨轴选一个最优**——
两轴故意隔离：合标准的可能实现错了，实现对的可能坏了约定，合并正好让一轴掩盖另一轴。

## 7. 收敛纪律（轮数上限 + 只复审增量）

**为什么有这一节**：agent 作者 + agent 审查者可以互相拉扯到无限。Anthropic Claude Code 团队实测：
一个 CLI PR **夜间被双方来回 50 多轮**，事后分析发现 **59% 的告警是早已存在的陈旧代码**——审查者不是在
发现新 Bug，而是在一轮轮挖历史存量（[原文](https://claude.dev/blog/solving-code-review-at-anthropic/)）。
治理后一轮即过的 PR 从 65% 升到 78%，需 5 轮以上的从 8.9% 降到 1.5%。

**本仓落地**（#71 会话实测跑了两轮：发现 5 条 → 修完再验，已有拉扯雏形）：

- **轮数上限 = 2**。第 1 轮 = 全量两轴；第 2 轮 = **只复审第 1 轮的修复**。
  第 3 轮**不再直接改**，强制退回一步重审技术路线（要么改口径、要么拆票、要么接受现状并记录）。
- **第 2 轮起只审增量**：固定点改为**上一轮的修复提交**（`git diff <fix-commit>...HEAD`），
  不重跑对整份 diff 的全文审查。理由：全量复审会把第 1 轮已判过的存量重新挖一遍（那 59% 的来源）。
- **报"类"不报"行"**：同一条发现涉及多处时，报**类别 + 代表位置**，促使一次性修整类，
  不要逐个 hunk 报（否则作者按行修，下一轮又发现同类另一处）。
- **不重复告警**：已报过且作者已明确"不修 + 理由"的（如"存量风格，另立票"），后续轮次**不再重报**。
  第 1 轮报过、作者裁决过的项，第 2 轮重复出现即为**违反本节**，应在报告里标注而非当新发现。
- **写进交付记录**：每轮结束时记录"本轮发现 N 条 → 处置 M 条 → 未处置及理由"，
  未处置项**必须**有去处（修 / 立票 / 显式接受），不得静默消失。

**判断"该不该开第 2 轮"**：只看一条——第 1 轮的发现里**有没有被判为必须修的**。
没有（全是 judgement call 且已裁决）就**不开第 2 轮**，直接提交；有则开，且只复审那些修复面。

## 8. 缺陷类登记（本仓栽过的，优先看）

**怎么用**：审阅前扫一遍本节的"类别"列——这些是**本仓已经栽过的形态**，同类优先搜。

**登记纪律**：
- 只登记**真缺陷**（违反了写下的标准 / 让某条判据失效）。judgement call 不进本表。
- **一条一类**，同类合并（"判定点重复"只有一条，不按出现次数开多条）——本表是**类别**表，不是 bug 列表。
- 守卫**后来失效**时，回到对应行更新落点，不要新开一行。
- 本表与 §3.1「失败长什么样」互补：§3.1 是**面的失败形态**（审阅时对照），本表是**类别的历史账**（审阅前扫一眼）。

**⚠ 本表是散文，没有机械守卫钉它**（`docs/**` 的守卫只有 `verify-doc-references` 的路径存在性）。
即：表里引用的守卫编号**可能随代码演进而失效**，而套件不会因此变红。缓解手段是**只在改守卫时顺手更新落点**
（本仓「单一事实源」口径的同一件事），以及审阅时把"本表引用的守卫仍存在且仍覆盖本类"当作一条**必查项**——
引用失效即 D3（文档说谎）的实例，按真缺陷处理。这条限制是**显式声明**，不是遗漏：把它做成守卫需要
"守卫编号 → 用例文件"的登记，代价高于收益（本表条目少、变更频率低）。
