# 退役判据正反样例集

> 本文件是匿名合成面：不含真实票号（判据出处见 `docs/agents/issue-tracker.md`
> 「退役判据：未接通 ≠ 无职责」节与复核 brief §2 的 5e 条）。

**匿名合成声明**：全部样例为合成场景，票据一律「某票」占位——不含任何私仓票面、业务数据
或本机环境信息。判据本体在 `docs/agents/issue-tracker.md`「退役判据：未接通 ≠ 无职责」节；
本文件只供**对照演训**：分诊 / grill / 架构分析会话照判据自测，Spec 复核
（`docs/code-review-brief.md` §2 的 5e 条）照「退役结论 vs 三件齐全」逐例核对。样例的
语义判断由评审承担，机械守卫（`tests/verify-retirement-criteria.mjs`）只钉文本送达与
入口在场，不判逐例语义。

六组覆盖两侧：**E1–E3 不得退役侧**（表面读数会误判成多余能力）、**E4–E6 可退役侧**
（正面依据与授权在场，正常放行）。每例走五件：**批准背景 → 表面读数 → 事实调查 →
判定 → 责任归属**。

## E1 缺消费者仍需保留（不得退役）

- **批准背景**：已批准目标 R「运营侧可一键导出经营报表」；模块 V 承接其中的报表生成
  半边，票面写明「消费端界面另票承接」。
- **表面读数**：架构扫查发现 V 全仓零调用——「没人用，删」。
- **事实调查**：四件事——①原定目标：R 的报表半边，批准记录在场；②缺失的连接：
  消费端界面票尚未实施（接线缺口在下游）；③拟承接的责任：消费端立票承接（TICKET
  EXIT），V 保持可调用状态；④事实边界：测了「当前无调用方」这一项，**没测**（也无法
  用它证明）「R 已取消」。
- **判定**：**不得退役**。这是消费端缺失——零调用是接线缺口线索，不是无职责证明。
  R 仍是被批准的未完成目标，删 V 等于静默取消 R 的一半。
- **责任归属**：架构分析会话不得把「零调用」写进清理清单；消费端缺口走 TICKET EXIT
  立票；复核（5e）发现「零调用 → 删」类 diff 无授权记录时报缺失。

## E2 缺数据源须补生产链（不得退役）

- **批准背景**：已批准目标 R「入库数据自动校验」；模块 W 承接校验逻辑，上游采集模块
  在另一张票里，尚未接通。
- **表面读数**：W 长期无数据流入，监控里是空转路径——「死代码，清理」。
- **事实调查**：四件事——①原定目标：R 在批准范围内；②缺失的连接：上游采集未接
  （生产端断点）；③拟承接的责任：接通生产链由上游票负责，W 侧无改动；④事实边界：
  「无数据流入」实测为真，但它只指向断点位置，不指向职责消失。
- **判定**：**不得退役，须补生产链**。这是生产端缺失——正确动作是追上游接线 /
  立票承接；若上游已永久取消，那是目标变更（human L2 拍板 + 授权记录），不是本模块
  自行推出的结论。
- **责任归属**：实施会话不得顺手删 W；上游断点上报排批；复核对照批准目标抓
  「空转 → 清理」误判。

## E3 仅部分职责被替代不得整体退役（不得整体退役）

- **批准背景**：模块 X 承担三个职责：输入校验、格式转换、旧格式兼容。一张实施票
  交付了新实现，覆盖校验与转换两个职责。
- **表面读数**：「X 已被新实现替代」，整体删除 X。
- **事实调查**：逐职责对照——新实现覆盖校验 ✓、转换 ✓、旧格式兼容 ✗（新实现明确
  不支持旧格式，而旧格式兼容仍是已批准职责，无取消记录）。
- **判定**：**不得整体退役**。同职责替代只覆盖一部分：被覆盖的职责可随替代退役，
  未覆盖职责（旧格式兼容）**保留**，退役面与保留面逐条列明。整体删除 = 未覆盖职责
  无声消失。
- **责任归属**：实施票的退役结论必须带未覆盖职责清单；「已全部覆盖」一笔带过 =
  复核报缺失；旧格式兼容的去留若要变更，走 human L2，不由删 X 的票顺路决定。

## E4 目标已获准取消可退役（可退役，且不是漏接）

- **批准背景**：目标 R「历史数据一键迁移」曾获批准，模块 Y 承接；实施中发现与只读
  快照契约冲突，human 拍板**取消 R**（gate 3 L2，授权记录写在票面评论，可回读）。
- **表面读数**：复核看到「Y 已删除 + R 从未交付」——「批准过的需求没交付，漏接！」
- **事实调查**：授权记录在场：R 的取消是 human 的明确拍板（三值去向里的「获明确授权
  的目标变更」），不是实施者自判；Y 的退役是取消的执行，不是逃逸。
- **判定**：**可退役**。已获准取消的目标按「已取消」读；把已取消误报为「漏接」和把
  未接通误判为「无职责」是同一枚硬币的两面——两者都跳过了授权记录核对。
- **责任归属**：取消通道 = human（实施者只能上报）；退役票引用授权记录（票号 +
  评论位置）；Spec 复核先查授权再定性——有授权记录 → 已取消；无记录 → 漏接 / 未完成，
  两种读数不可互换。

## E5 同职责替代已覆盖可退役（可退役）

- **批准背景**：模块 Z 承担配置加载职责；新实现（含热重载）已交付，票面 AC 含
  「逐项替代 Z 的配置加载行为」并附对照证据。
- **表面读数**：与 E3 表面读数相同（「被替代了」）——但这次调查支持它。
- **事实调查**：逐职责对照——配置项解析 ✓、优先级合并 ✓、加载失败告警 ✓，覆盖证据
  在场（对照用例 + 命令读数）；Z 无其余职责；消费方切换路径已列。
- **判定**：**可退役**。三件齐全：正面依据（逐职责覆盖证据）✓、影响范围（消费方
  切换去向）✓、未覆盖职责（无，逐条确认过）✓。这是正常退役，不需要额外确认轮。
- **责任归属**：替代票的 AC 与证据承担覆盖证明；退役执行票核对三件即可放行；
  复核发现覆盖清单缺项时按 E3 处理。

## E6 真实不可达分支可清理（正常清理）

- **批准背景**：模块 M 的状态机里有一个分支判断 `status === "archived"`，而全仓
  没有任何生产者产出该状态值（缺陷类 D12 形态：永假分支）。
- **表面读数**：「这个分支永远走不到」——与 E1/E2 的表面读数同形（「用不上」）。
- **事实调查**：区别在证据类型——这是**结构性**证据（没有生产者、没有出口、状态值
  无声明来源），不是**历史性**缺口（M 没有已批准却未接通的原定接线；「archived」
  状态本身无批准记录）。
- **判定**：**可清理，正常走**。真实不可达分支的删除是既有死分支清理纪律（D12）
  的正常执行，**不新增人工确认轮**；清理说明里写明「无生产者」的结构证据即可。
- **责任归属**：实施 / 复核照既有纪律删；不需要授权面——但一旦调查发现该状态
  **本应有**生产者（即它是未接通能力的残留），判定翻转为 E2：补链或立票，不是删。

---

**对照速查**：E1（零调用）与 E6（永假分支）的表面读数几乎相同，判定相反——分界是
**有没有批准过的职责链悬在后面**（历史性缺口 → 保留 / 补链）vs **结构上从未存在过
职责**（结构性证据 → 清理）。E4 与「漏接」的分界是**授权记录在场与否**。
