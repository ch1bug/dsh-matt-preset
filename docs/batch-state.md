# batch-state —— 批次状态文件的形状（单一事实源）

本文件是 `.scratch/batch-state.md`**形状的唯一事实源**：模板、必需字段、落盘契约都写在这里。
工作流正文（`workflow-body.txt` 的 `@@ batch-mode` 节）、enforcer 的提醒文案与断言用例
**只留指针、不复述字段**——字段要改，先改这里，再让指针面跟上（D27 低频变更；量表未变不改机制，D29）。

**载体归属**：批次机制（触发、路径、命名、marker、状态行）必须落在**仓内**——`~/.dsh/skills/`
是机器本地、不随 clone 分发（#71 设计点 7）。本文件即那份仓内载体。

## 模板

批次宣告时把下面这份骨架复制成 `.scratch/batch-state.md`（`.scratch/` 是 gitignored 工作区，
不进仓、不随 clone 分发）：

```markdown
# Batch state — <批次名>

- **宣告**：<日期 / 来源指令>；批次意图：<一句话，为什么这批值得攒>。
- **成员**：<票号列表，含顺序>；**结束点**：<最后一票的票号 + 收束判据>。
- **模式**：批次内逐票本地提交 + 本地验证，不单独 push；批末一次 push。

## 成员与顺序

状态列口径：`ready-for-agent`（未开工）/ `done`（已完成，本地提交后标）—— 票数取数见「必需字段」。

| # | 票 | 状态 | 说明 |
| --- | --- | --- | --- |
| 1 | #<票号> | <状态> | lane=<泳道>；后继票=#<票号> |
| 2 | #<票号> | <状态> | lane=<泳道>；后继票=#<票号> |

## 结束点

<批次收束的判据：全部完成 + 每票本地验证绿 + 未推送清单 → 批末总结 → human 确认 → 一次 push>

## 进度日志（每票结束更新）

- <日期>：**#<票号> 实现完成** → 本地提交 `<sha>`（**未 push**）。
  Progress 行三要素（证明命令 / exit code / 证据路径）：`<证明命令>` → exit `<code>` → `<证据路径>`。
  **未推送清单**：未推送的 `<sha>` 逐条列出，**结尾必带自称笔数** `（<N> 票）` ——
  `N` 取自 `git rev-list --count origin/<branch>..HEAD`（**取数命令契约**见下节）。

retro: done @ <commit>
```

`retro:` 那一行**不是模板的可选装饰**：它是批末 retro 的**完成标记**，enforcer 读它来判断
「这批的批末 retro 是否已经跑过」（`RETRO_TRIGGER.retroMarker`，存在性判据——不解析表格、
不校验其它字段）。**写这一行的是 agent**（正文规则，见 `workflow-body.txt` 的 `@@ batch-mode` 节）：
enforcer 是 reminder-only，**只读标记、不写文件**。

⚠ **两个标记、两件事**（勿混）：`retro:` 说的是「批末 retro 已**跑**」，而它写在批末 push
**之前**——所以**它单独并不能**把聚合呈现限制到每批一次（跨会话会重复聚合，实测 3 会话 → 3 次）。
真正抑制重复**呈现**的是**第二个**存在性标记 **`.scratch/retro/.aggregated`**
（`RETRO_TRIGGER.aggregatedMarker`）：agent 在**真的呈现过**聚合之后写它。已聚合批次的后续会话
**不再聚合、不再重复呈现**，但**仍跑本会话 retro 并落盘自己的候选**——每批至多一次约束的是
**呈现**，绝不是素材（**不静默丢素材**）。两个标记都由 agent 写、enforcer 只读；`.aggregated`
是 retro 素材目录里的 dot-file，与候选文件同生命周期（叫 `.md` 会被聚合自己的 `read every
.scratch/retro/*.md` 误当候选读走）。

## 必需字段

| 字段 | 判据 | 缺席的后果 |
| --- | --- | --- |
| **成员** | 宣告成员与顺序（票号 + 次序），与批次宣告逐字一致 | 无法判断「还有谁」——AUTO-HANDOFF 没有依据（D33） |
| **结束点** | 最后一票 + 收束判据 | 批次不知道什么时候停；防堆积护栏 (c) 失效（D31） |
| **Progress 行三要素** | **证明命令 + exit code + 证据路径**（测试输出本身算证据，不需另立文件） | 缺任一要素的行是 **BLOCKED，不是 done**——这是「已验」与「以为已验」的边界 |
| **lane 标注** | 该票跑在哪条泳道（A / B / C 或沙箱车道） | 批末无法回收泳道准确率（D38） |
| **后继票** | 本票之后是谁（批内顺序固定，宣告即指派） | 收尾会话只能停等 human 说「开下一票」——AUTO-HANDOFF 的路由断了 |
| **`retro: done @ <commit>`** | 批末 retro 已**跑**、commit 为聚合呈现的依据点 | 无法判断批末 retro 是否跑过；重复**呈现**的真正抑制靠 `.scratch/retro/.aggregated`（见上） |
| **成员表「状态」列** | 「成员与顺序」表的 `状态` 列：**以空白分隔的首词 = `done`** = 该票已完成（本地提交后标；`done` / `done @ <sha>` 都算，`done（#114）` / `done@sha` 这类**无空格粘连不算**）。**已完成票数** = 这些行的行数，由 C9-guardrail **机械解析**（按**列名**定位该列，不写死列序；见「笔与票」节） | 护栏 (b) 的**票数**取不到 → 护栏读 0 就等于被废掉。**禁止**另加手抄的「已完成票数」字段：手抄必漂（#115 覆辙），票数只许从这张表的结构推导 |
| **未推送清单** | 进度行尾 `（<N> 票）` 里的 **N** = **最后一条**自称的未推送**笔数**（字段名里的「票」是历史名字，**量是笔**）；N **只许**由 `git rev-list --count origin/<branch>..HEAD` 产出（理由见下节） | 批末 push 的输入读它（C9 会对账）；**但它不进护栏比较**——护栏 (b) 读的是上一行的**已完成票数**（笔 ≠ 票，见「笔与票」节）；取错命令会让 5 笔读成 1 笔，而 C9-live **只报不阻断**，于是错数会跟着批末 push 走 |

**恢复时以本文件为唯一事实源**，不与记忆或环境「凭感觉对齐」：文件缺失、过期或与观测到的
环境（git HEAD / worktree / 文件态）矛盾 → **停下问 human**，不猜、不自行修正记录（D39）。

## 取数命令契约（「未推送清单」只许一条命令）

**未推送笔数一律用 `git rev-list --count origin/<branch>..HEAD`。** 别用 `Measure-Object`
一类**行数统计**代劳——理由不是风格偏好：

- **`| Measure-Object`（默认，无 `-Line`）逐**对象**计数，不是逐行**。触发条件是
  **输出没有被逐行送进管道**——把多行输出作为一个 string 对象交给它（变量快照 /
  `-InputObject (git log …)`），整段就被数成 **1**：本机（PowerShell 7.6.7 + git
  2.55.0.windows.5）实测 4 笔报 **`Count = 1`**、8 笔**仍报 1**（`-Line` 才逐行、报对，
  与 `rev-list` 一致）。
- **另一个同向的坑**：`Measure-Object -InputObject (git log …)` 恒报 **1**——它比默认形态
  更顽固（默认形态至少随对象数变，这个连 8 笔都还是 1）。两种形态**都朝向危险侧**，
  所以契约钉的是**命令白名单**，不是"哪个参数对"。
- **为什么这个错法特别贵**：它**恰好朝向危险的一侧**——把「≥5 笔」读成「1 笔」，
  人还以为自己数过了（#77 / #113 / #48 三次复发，跨会话 retro 聚合记为 4/4 会话）。
  ⚠ **#119 起它「贵」在哪变了**：护栏 (b) 读的是**票数**（见下节），所以错读笔数**不再**
  「绕过护栏」——失真的是**未推送清单本身**（批末 push 的输入），而 C9-live 对账**只报不阻断**
  （工作树领先状态文件是提交时点的正常态），于是错数会被如实记进状态文件、跟着批末 push 走。
  #115 时代那句「绕过护栏且不报警」是**当时**（护栏读笔数）的形态，别再写回来。
- **所以是契约，不是建议**：`tests/verify-batch-state.mjs` 的 **C9** 机械对账（下面「机器守卫」
  一节）会读活文件里**最后一条**未推送清单的声称，并**用 `rev-list` 那张显式白名单**去对账——
  两个数字不一致就**响亮报数**。⚠ C9 只报**声称 ≠ 实测**，**不判断你用了哪条命令**
  （工具面判不出来，不猜）；命令这一条靠**本节契约 + C9c 契约在场断言 + C9b 机械演示**共同钉住。

## 笔与票：两个量，别混着比（#119）

同一份状态文件里有两个**不同量纲**的数。读错哪一个，防线都会失真——一个是"漏报"，另一个是"狼来了"：

| 量 | 取数（唯一口径） | 谁读它 | 单位 |
| --- | --- | --- | --- |
| **未推送笔数** | `git rev-list --count origin/<branch>..HEAD` | 批末 push 的输入（C9-live 对账） | **笔**（提交） |
| **已完成票数** | 成员表「状态」列**以空白分隔的首词为 `done`** 的行数（机械解析，**不是手抄字段**） | 护栏 (b)（D31 (b)；机械闸即 C9-guardrail） | **票**（票号） |

- **别拿笔比票**：A 批实测——5 票全部完成时未推送 **14 笔**。拿笔数比 5 会喊「超护栏」，
  而按票数（5 票）护栏**未触发**。误报方向是「没超也喊超」，后果是**狼来了**（真该停时人
  已习惯性忽略）；它与 #115 治过的「把 ≥5 **笔**读成 1 **笔**」互为镜像（那侧是漏报，
  这侧是误报）——**但两者错在不同量上**：漏报那侧错的是笔数（影响未推送清单与批末 push 输入），
  误报这侧错的是把笔数当票数（影响护栏）。#115 时代「绕过护栏」的说法只对当时成立。
- **判据是「超过」5 票**（票数 **> 5** 才喊，5 票不喊）：5 是**批的成员上限**（**D32**；
  护栏 (b)「未推送达 5 票」里的 5 见 **D31 (b)**），所以正常批拿不到第 6 票——这道闸喊出来时，
  信号是「批超出宣告上限 / 成员表漂了」，**不是**"该 push 了"（push 节奏仍走 D31 的批末总结门）。
  恰好 5 票时读数会附一行边界提示，说明正文 D31 的暂停门在那一刻仍在，只是机械闸按「超过」才喊。
- **两条轨别混（这是本节最容易读错的地方）**：
  - **规则轨**（human 规则，权威在正文 `@@ batch-mode` 的护栏 (b) / **ADR-0002** 与 D31 (b)）：
    「未推送达 **5 票**或 1 周 → **暂停并报告**、请求 push 检查点」——它在**达到** 5 时就让人停。
  - **机械闸轨**（本文档定义、C9-guardrail 执行）：**超过** 5 票才**喊**；5 票不喊，只附一行边界提示。
  - 两者**不冲突**：规则管「该停」（达到 5 票正好是批末收束点——按 (c) 本来就要收尾于 push），
    闸管「喊不喊」（重复喊一个正常收束点就是狼来了）。
  - ⚠ **别把闸的读数当成规则轨的读数**：闸读**已完成票数**（成员表 `done` 行），规则轨读**未推送票数**。
    批内不单独 push 时两者同向；但**批中若曾获 push 检查点**，未推送票数可能已归零、而 `done` 仍是 6 ——
    此时闸喊的是「批超出 **D32** 的 5 票上限」（违规形态 → 先暂停报告），**不是**「未推送达 5 票」。
    规则轨要不要触发，按它自己的「未推送票数 / 1 周」量判断，别拿闸的读数替代。
- **取不到票数就响亮**：无活文件（非批会话）→ **loud skip**；活文件在但成员表解析失败
  （缺「成员与顺序」节 / 节内无表格 / 表头无「状态」列 / 某行缺列）→ **✗ 并写明原因**，
  **绝不静默当 0**（0 是"没超"方向，静默 0 会把护栏整个废掉——同 C9 对"取数不可用"的处置）。
- **笔数照常列出**：C9-live 的对账与「未推送 N 笔」的展示都保留（笔数有自己的信息价值），
  只是它**不参与**护栏比较；输出里两个量**各自命名**，不再出现「N 笔 … 超 M 票护栏」这种混单位句。

## 落盘契约（retro 候选）

- **位置与命名**：`.scratch/retro/<batch>-<session>.md`——一批一目录前缀、一会话一文件，
  同批可枚举、跨会话可读。
- **内容**：候选（按严重度排序）+ **证据（命令 / 输出）** + 来源（**会话 id / 票号**）
  + 未落地原因。**只写候选、不落地**——落地仍需 human 拍板（D22 / D27）。
- **只写候选不是外部动作**：写本地候选文件不触外部动作门（D21 只管 push / 关票 / 建 issue），
  所以**免确认、不阻断**收尾——会话继续，不需要停下来等确认。
- **幂等**：同会话重跑**覆盖同名文件**，不追加、不产生副本。
- **批末聚合**：先跑**本会话**一次 retro，再读齐同批已落盘的文件 → **去重合并**（同一问题在
  多个会话重复出现要合并并记次数——这正是聚合的价值）→ 按严重度排序 → **一次呈现**给 human，
  每条标注来源票号 / 会话。批末不再完整重读同批历史会话（省掉重复重读）。
- **每批至多一次**：**呈现**由 `.scratch/retro/.aggregated` 抑制（跨会话，agent 在呈现后写）；
  `retro:` 只表示批末 retro 已跑，不作呈现抑制。批内**落盘**每票一次（幂等覆盖），已聚合批次的
  后续会话照样落盘——约束呈现，不约束素材。
- **不静默丢素材**：收尾用**事实探测**（`git log origin/<branch>..HEAD` / `git status -sb`）判「已推」；
  探测到「已推但无落盘」→ 补跑或记 marker，绝不静默丢。

## 触发面（正文与 enforcer 共用的口径）

**只有真的 push 调用**触发 retro——判定输入恒为 `(toolName, argv)`（工具层 + 命令层）。
会话 / 思考 / 文档里出现「推送 / push」**字词**一律**不触发**（本仓 handoff 正文即反例）。
间接 push（经脚本）与 PTY 分片写入**一律不触发**，交事实探测兜底（**宁严勿宽**：误触发白跑一次
retro + 垃圾候选污染批末聚合，比漏一次更贵）。判定面逐字口径见 `docs/workflow-enforcer.md`。

## 适用车道（哪些车道适用这套规则、各自无需什么）

三条车道**共用**同一份批末收尾规则（本文件的形状 + `retro:` / `.aggregated` 标记 + #71 的
`(toolName, argv)` 触发面）——差别只在**收尾会话在哪、靠什么信号判"批末"**，不在机制。
各车道**只声明适用范围，不复述字段**（形状见上文；车道权威口径见各自 ADR）：

| 车道 | 适用什么 | 无需什么 |
| --- | --- | --- |
| **matt 批**（白天，ADR-0002） | 宣告批次 → 写 `.scratch/batch-state.md`；批末 push + CI 全绿 → 主会话跑批末 retro。**规则原生于此**，其余车道是它的复用者。 | 无需专用机制——它就是 #71 的基准形态（收尾会话 = 批末那个 main-cwd 会话）。 |
| **沙箱夜批 Y**（ADR-0003，落地 #73） | 同上：批末 push + CI 全绿 → **主会话**跑批末 retro（聚合 `.scratch/retro/*.md` → 去重一次呈现 → 写 `.aggregated` → 写 `retro: done @ <commit>`）。 | **复用 #71 的标记**（`.scratch/batch-state.md` + `retro:` / `.aggregated`）——**无专用状态文件、无专用标记、无新机制**。容器内**不跑 retro**：夜间只把 digest 的「retro 素材」段当**喂料**（喂料不参与判定）；候选交 human 的**决策路径只在清晨主会话**（CI 全绿信号正好落在那一刻）。 |
| **Teams 流水线**（ADR-0006） | 同上：批末 push + CI 全绿 → **Lead 会话**跑批末 retro（聚合 `.scratch/retro/*.md` → 去重一次呈现 → 写 `.aggregated` → 写 `retro: done @ <commit>`）。流水线是"一个会话一条流水线"，票的 grain 降到 teammate 任务，**收尾动作恒由主 cwd 的 Lead 执行**。 | **复用 #71 的规则与标记**（`.scratch/batch-state.md` + `retro:` / `.aggregated`）——**无专用信号、无专用状态、无新机制**：收尾处主 cwd 里有 batch-state.md、批末 push 后有既有 CI 绿信号，两个前提**按构造即成立**，故无需为本车道另立任何东西。 |
