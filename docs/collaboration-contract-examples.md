# 协作契约正反样例集

> 本文件是匿名合成面：不含真实票号（判据出处见 `docs/agents/issue-tracker.md`
> 「协作契约：项目显式启用的单票协作」节与复核 brief §2 的 5f 条；起步模板见
> `docs/collaboration-starter-template.md`）。

**匿名合成声明**：全部样例为合成场景，票据一律「某票」占位——不含任何私仓票面、业务数据
或本机环境信息。判据本体在 `docs/agents/issue-tracker.md`「协作契约」节；本文件只供
**对照演训**：协作会话照判据自测（适用 → 授权 → 认领 → PR 四步），Spec 复核
（`docs/code-review-brief.md` §2 的 5f 条）照「适用面 / 授权分层 / 主责闭环」逐例核对。
样例的语义判断由评审承担，机械守卫（`tests/verify-collaboration-contract.mjs`）只钉
文本送达与入口在场，不判逐例语义。

六组覆盖两侧：**P1–P2 正例侧**（两个采用入口各自走到一张等候合法批准的 PR）、
**N1–N4 反例侧**（无授权 / 缺主责 / 主责自批冒充独立批准 / 模板未随安装分发）。每例走
五件：**契约背景 → 会话读数 → 判据核对 → 判定 → 责任归属**。

## P1 已有规约接入（正例：权威入口，不复制第二套）

- **契约背景**：某项目已有协作制度（治理文档写明「PR 需一位维护者批准 + CI 绿」，可回
  读）——权威入口在场。
- **会话读数**：一位外部协作者的会话认领某票（认领后回读票面，票面 AC 已更新过一次，
  以回读为准），实现后提交 PR：描述列明主责（本人）、授权依据（票面评论的项目确认）、
  当前提交验证（命令 + 退出码 + 证据路径）、项目要求的批准（一位维护者），PR 回指票号。
- **判据核对**：适用——项目采用记录在场（治理文档），启用成立；已有制度 → 沿治理文档
  的权威入口，会话没有另造一套批准规则；主责一位、票与 PR 互指、认领后回读、四件事
  齐全。
- **判定**：**合规**。PR 停在「等候合法批准」态——非作者批准尚未发生，主责不宣称完成。
- **责任归属**：批准由项目维护者（非作者）给出；会话不得替项目催批或虚构批准；Spec
  复核（5f）核对四件事齐全 + 批准确实来自非作者。

## P2 空白项目采用模板（正例：起步模板 + 个人路径保留）

- **契约背景**：另一项目**无任何协作规约**，参与者决定启用协作——从随 preset 分发的
  起步模板采用：复制进项目仓库、填好占位符，并在置顶 issue 记录「本项目采用本协作
  契约」（可回读的采用记录）。
- **会话读数**：采用后，一位协作者会话认领某票 → 实现 → PR 列四件事（主责 / 授权依据 =
  采用记录 + 契约条目 / 当前提交验证 / 项目要求的批准 = 模板默认的一位非作者），等候
  批准。同一 preset 的用户在**另一个未启用协作的个人项目**里照常单会话工作，没有被
  要求任何团队审批。
- **判据核对**：适用——采用记录在场（空白项目通过模板确认启用）；模板随安装分发在场
  （消费者可访问）；默认 PR、至少一位非作者批准、项目约定的验证证据都在模板正文；
  未启用的个人项目**没有**被加审批义务。
- **判定**：**合规**。两个项目各自路径正确——协作项目走 PR 闭环，个人项目无审批义务。
- **责任归属**：采用记录由项目方写（不是 agent 代声明）；平台保护（分支保护等）由项目
  自行决定，preset 与 agent 不代配；复核对照「适用面」核对两个项目的义务面各自成立。

## N1 无授权启用（反例：凭贡献者数量推断 + 虚构授权）

- **契约背景**：某项目**没有**协作规约，也没有任何采用记录；仓库有十几个贡献者。
- **会话读数**：会话看到「贡献者不少」，自行宣布「本项目是团队协作，本票需要一位非作
  者批准才能合并」，并在 PR 描述里写「已获项目授权」——实际上没有任何可回读的采用
  记录或授权记录。
- **判据核对**：适用判据——**不凭贡献者数量推断**（贡献者多 ≠ 启用）；无采用记录 =
  未启用 = 个人路径，无审批义务；「已获项目授权」无记录支撑 = **虚构授权**（缺项必须
  如实呈现，不能自动虚构批准者）。
- **判定**：**违规**。两处错：凭数量推断启用 + 虚构授权。正确形态：无记录 → 个人路径
  照旧；若确需协作审批，先让项目方落采用记录（human 拍板），缺项如实报。
- **责任归属**：会话不得代项目宣布启用或授权；复核发现「无采用记录却套用审批义务」或
  「授权宣称无记录」时报缺失；启用决策属项目方（gate 3 决策边界同族——授权归属不由
  agent 自判）。

## N2 缺主责（反例：多人参与无人负责，票与 PR 脱节）

- **契约背景**：某项目已启用协作模式（采用记录在场），多人参与同一事项。
- **会话读数**：两个协作者各自改了同一票涉及的面，没人声明主责；实现散在两个 PR 里，
  都不回指票号；票面也没有 PR 记录——票与实现脱节。
- **判据核对**：主责判据——**每票一位主责**（多人参与不限，但主责恰一位）；**issue /
  PR 关联对应实现**（PR 回指票、票面记录 PR）。
- **判定**：**违规**。缺主责 + 票 PR 脱节。正确形态：先在票面协调出一位主责（重复认领
  先协调），两位参与者把工作归到一张票、一个 PR（或按票拆分后各认各的），互指补齐。
- **责任归属**：主责缺位时参与会话不得各自推进到底（先协调）；复核抓「票无主责记录 /
  PR 不回指票」；移交若有，原主责声明 + 新主责接认两步都落在票面。

## N3 主责自批冒充独立批准（反例：自报完成不替代批准）

- **契约背景**：某项目已启用协作模式，契约要求「至少一位非作者批准」。
- **会话读数**：主责提交 PR 后，批准记录来自**主责自己的另一个会话 / 另一个身份**（同
  一作者的变体），随后 PR 描述写「已获批准，合并」——批准者实质是作者本人。
- **判据核对**：批准判据——**至少一位非作者批准**；**主责自报完成不替代批准**（批准是
  独立审阅事件，不是进度报告；同一作者的会话 / 身份变体不构成「非作者」）。
- **判定**：**违规**。冒充独立批准 = 批准缺失 + 虚构记录。正确形态：PR 保持「等候合法
  批准」，由真正的非作者审阅后批准；批准人不明或存疑时如实报缺项，暂停合并——本地
  无关实施继续。
- **责任归属**：批准独立性由项目审阅承担（机械面不判身份——D16b 同族边界，但「同一
  作者宣称已获批」无独立审阅记录时复核报缺失）；合并放行在批准存疑时暂停，不全停
  本地实施。

## N4 模板未随安装分发（反例：起步承诺失守）

- **契约背景**：某空白项目想启用协作，participants 依赖 preset 的起步模板；某次分发
  面变更把模板文件从安装白名单里漏掉——注入文本仍写着模板指针，但安装位上模板
  不存在。
- **会话读数**：会话按注入文本指引「采用起步模板」，去读模板文件——安装位上缺席；会
  话没有如实报缺项，而是凭记忆手写了一份「模板」当作项目契约（内容与模板漂移，批准
  门槛写成了「作者自查即可」）。
- **判据核对**：模板判据——起步模板**随安装分发**（消费者可访问，payload 白名单在
  场）；缺席是**缺项**，必须响亮呈现并暂停采用，**不能凭记忆补写**（手写副本 = 第二套
  制度 = 漂移种子，且丢了非作者批准这类默认门槛）。
- **判定**：**违规**。正确形态：模板缺席 → 如实报「模板不可达」，暂停采用，等分发面
  修复；机械面由 payload 白名单断言抓（模板不在 `files` 白名单 = 守卫红）。
- **责任归属**：分发面由守卫钉（`tests/verify-collaboration-contract.mjs` 的分发可达
  断言）；会话不得手写替代模板；复核发现「凭记忆补写的契约」时按 N1 虚构授权同款
  处置。

---

**对照速查**：N1 与 P2 的表面起点相同（「项目想协作」），分界是**采用记录在场与否**——
记录在场 → 启用成立（P2 走模板闭环）；记录缺席 → 未启用 + 缺项如实呈现（N1 不得推断
或虚构）。N3 与合法批准的分界是**批准者是否独立于作者**——同一作者的会话 / 身份变体
不构成非作者（机械面不判身份，独立审阅记录缺失即复核报缺失）。N4 与「模板在用」的分
界是**分发面在场与否**——指针写着而文件缺席 = 缺项响亮呈现，不是凭记忆补写。
