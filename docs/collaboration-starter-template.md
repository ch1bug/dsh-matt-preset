# 协作契约起步模板

> **这是什么**：一个项目**没有既有协作规约**时可以采用的起步模板。它是**可编辑起点**，
> 不是自动生效的规则——项目确认采用（复制进项目仓库并声明采用）后，它才成为该项目的
> 协作契约；preset 与 agent **不自动配置任何平台保护**（分支保护 / required reviews 等
> 平台设置由项目自行决定）。项目已有协作制度时，采用其权威入口，**不要**用本模板复制
> 第二套。
>
> **采用方式**：把下文「模板正文」复制到项目仓库（如 `CONTRIBUTING-collaboration.md`
> 或治理文档一节），按项目实际填好 `<占位符>`，并在一条可回读的记录（提交 / 治理页 /
> 置顶 issue）里声明「本项目采用本协作契约」。**没有这条采用记录 = 协作模式未启用**，
> 参与者继续走个人路径，不承担团队审批义务。

---

## 模板正文（复制以下内容到项目仓库后按需修改）

# <项目名> 协作契约

本项目**显式采用**协作契约（采用记录：<提交哈希 / 治理页链接 / 置顶票>，<日期>）。
本契约只约束**跨工作区协作**（多人经 issue 认领 → 实现 → PR 供项目批准）；未采用前的
单会话路径不受影响。

## 1. 适用

- 本契约自采用记录在场起生效；**不凭贡献者数量推断**——协作者数量、PR 频度、仓库
  公开性都不构成启用或停用依据。
- 个人路径保留：单人工作、非协作模式的票，不需要任何团队审批。

## 2. 授权分层（按事项，不按在场者）

| 事项 | 授权人 / 流程 | 记录面 |
| --- | --- | --- |
| 需求授权（接受一条需求 / 定范围） | <谁拍板：维护者 / 票面评论确认 / 会议记录> | <哪里可回读> |
| 跨模块接口授权（模块间契约变更） | <谁拍板> | <哪里可回读> |
| 合并 / 发布授权（一次合并或发布放行） | <谁拍板> | <哪里可回读> |

- 在场属性**不推导**授权：参与讨论 ≠ 仓库写权限 ≠ 代码审阅职责 ≠ 合并放行权，任何
  两个都不互相推出。
- **授权不清时只暂停相关决定**：依赖该授权的事项停下等授权，本地无关工作继续。

## 3. 主责与认领

- **每票一位主责**（owner），多人参与不限；主责对交付证据与 PR 陈述负责。
- 认领动作：<项目形态——设 assignee / 票面评论「我认领」>；**认领后回读票面**（AC 与
  口径以回读到的为准）。
- **重复认领先协调**：发现他人已认领同一票，先在票面协调谁接、怎么分，不抢注、不
  静默并行。
- **换人明确移交**：原主责声明移交 + 新主责接认，两步都落在票面。
- **指派是职责记录，不是锁**：assignee 不构成写权互斥——文件写权冲突按各项目自己的
  写域纪律处理。

## 4. PR 验收（默认合并路径）

- **默认 PR**：协作交付走 PR（例外与替代形态：<项目若有，写在这里>）。
- PR 必须列明四件事：**主责**、**授权依据**（票面授权记录 / 契约条目）、**当前提交的
  验证**（命令 + 退出码 + 证据路径）、**项目要求的批准**。
- **批准门槛：至少一位非作者批准**（<项目若要求更多人数或特定审阅者，写在这里>）。
- **主责自报完成不替代批准**：作者本人（含其另一个会话 / 身份）宣布完成不构成批准。
- **合并规则不明 → 暂停合并**：放行人 / 批准人数不明时暂停合并并如实报缺项；本地
  无关实施继续，不自动全停。

## 5. 验证要求

- <项目约定的验证命令与证据形态：如「PR 描述附 `<验证命令>` 的输出，标注退出码与
  证据路径」>。
- <环境侧断言的跳过如实声明：跳了什么、为什么，写进 PR 描述，不静默>。

## 6. 边界

- 本契约**不**承诺实时通知 / 在飞变更回执（那是消费方与项目政策的职责）。
- 本契约**不**建设跨机器权限服务、共享工作树锁、自动合并；平台保护配置由项目自行
  决定，本契约的存在不等于任何平台门禁已开启。
- 外部动作（push / 建票 / 发布）照项目既有确认门执行，本契约不放松任何门。
