# 0017 — 注意力经济学作为工作流优化目标轴：门 3 三层分级 + 收口卡双形态（#179）

状态：已采纳（2026-11-06 human 拍板，AskUserQuestion 三答在案；2026-11-07 入册）
前置：[0010-workflow-core-plugin.md](0010-workflow-core-plugin.md)（七门正典落点）、[0016-workflow-components.md](0016-workflow-components.md)（组件机制，轴 B 正文段落点）

## 背景

human 2026-11-06 方向裁决（原话归纳）：**工作流在尽可能保证质量与治理的前提下，降低对
人注意力的损耗**。配套三答：① 门 3 采三层分级；② 收口卡采「卡 + 正文双形态降级」；
③ 落地采「决策票 + 分波实施」。

理论底座：外部文章《AI 时代人的注意力经济学与认知负荷管理》（2026-11-06 human 提供，
链接见票 #179 尾）。核心模型：AI 蒸馏掉低认知缓冲带后，人的注意力/判断力是唯一不可
再生素；**注意力损耗 ≈ 中断次数 × 每次装载成本**；判断力在连续微审批后退化为橡皮图章。

本仓现状（入册时实测）：

- 七门在 `workflow-body.txt` `@@ workflow-enforcement`（L30–66），门 3「DECISION
  BOUNDARY」（L44–46）是**一层形态**——所有真决策一律立即问并等待，不区分「这题值不
  值得打断人」。
- 非阻塞问题**攒批**的机制已有一半：enforcer 的 GRILL QUESTION CONTRACT 自带 batch
  mode（`workflow-enforcer.mjs:1263-1264`，human 显式 opt-in 才 ≤5 问一收口）、批宣告
  batchDeclare 面、批末问批次。缺的是「agent 主动把不阻塞的题攒到阶段边界」的**成文纪律**
  ——现在 L1 类问题在正文里没有名字，只能走 L2 立即问或被静默吞掉（两头都错）。
- 卡面机制上游已备：`@deepseek-ai/dsh-action-cards`（rc.1 实读
  `tests/node_modules/@deepseek-ai/dsh-action-cards/README.md`）——`propose_action` 工具
  条件注册（kind 的 skill 在当回合被根 Agent 的 `skill` 调用装载才 eligible；subagent 或
  code 发起的调用被拒）；**一回合一张卡**（同回合第二次调用被拒）；卡在**回合结束后**
  出现，用户不动作则不执行任何东西；`queuedMessageLimit` 默认 2（≥2 条排队消息时拒出卡，
  别在用户已经积压时再添一张）；kind 由 kind 包自己的插件经 `ctx.actionCards.register(kind)`
  注册（卸载即移除，卡上动作随之拒绝为 unavailable，仅 Not now 仍可关未启动的卡）；新卡
  替换所有未启动旧卡；动作前 kind 的 `reconcile` 先从 Session 外状态更新卡。
- 服务可达性：personalized-recommendations bundle 携带 action-cards 服务与其浏览器半边
  （上游 README「Use this package」节）；`tests/fixtures/official-runtime-deps-v1.json`
  `publishedDependencies`（90 项，默认安装集）含
  `@deepseek-ai/dsh-personalized-recommendations`（2026-11-07 读数）——即**默认安装集里有，
  但运行时是否激活（propose_action 是否注册可见）属环境侧事实**，实施票须 live 验证，
  双形态降级覆盖缺席（见 §4）。

## 决策

### 1. 优化目标轴成文

工作流的优化目标在「质量与治理」之后加一条轴：**降低 human 注意力损耗（中断次数 ×
装载成本）**。它是排序原则，不是豁免原则——质量与治理不让步（§3），在这条约束下，
**能不自断的不打断、能攒的不逐条、必须打断的把装载成本降到最低**（一次问清，问完即走，
不让人反复回到同一题）。

### 2. 门 3 三层分级（L0 边界判定表）

门 3 的门面语义不变（**真决策不替人做**），内部分三层：

| 档 | 判定 | 处置 |
| --- | --- | --- |
| **L0 自决** | 四条**全部**满足：可逆（git 可回退、无外部副作用）∧ 票内范围 ∧ 与仓内既有模式一致（不引入新模式）∧ 不触七门任一门 | 直接决定 + **逐条记录**（票面决策日志）；阶段边界汇总 **L0 清单供人审计** |
| **L1 攒批** | 需 human 输入但**不阻塞**当前步推进 | 攒到阶段边界，问批次一次性问（机制已有，缺的成文纪律由本轴补上） |
| **L2 立即问** | blocker（当前步无法继续）/ 不可逆或外部副作用（含 D21 清单）/ recovery 状态完整性 / 范围扩张、AC 改写、triage 三选一 | 立即问并等待（现行门 3 形态） |

判据方向：先试 L0（四条有一个不满足即出局），再试 L1（human 输入是否阻塞当前步），
都不是才 L2。**L0 的第四条「不触七门任一门」意味着任何含糊回退到 L1/L2**——分级
宁可上问，不自断。

L0 的对冲（对文章「橡皮图章」警告的正面回应）：L0 不是免审——阶段边界的 **L0 清单
审计**（人扫一眼本阶段 agent 自决了什么）+ 轴 C 的机器自检前移（能跑门禁的必须自己跑绿）
+ 轴 A 的边界审计（爆炸半径大的自决即使可逆也升 L1）。审计非免审，频率换深度。

### 3. 不变量清单（治理不让步）

1. **七门全部保留，语义不降级**；本决策只改门 3 的内部分级，门面本身不变。
2. **四类永不进 L0/L1，恒为 L2 立即问**：
   - D21 外部动作（push / 装机 / 发版 / tag / 建票等，门 6 面）；
   - recovery 的 STOP-and-ask（状态完整性，`@@ enforcement-recovery`）；
   - 隐私面（个人/本机环境串不进仓，AGENTS.md §隐私硬规则）；
   - 范围扩张与 AC 改写、triage 三选一（既有拍板保留，门 5/7 面）。
3. **质量保证方式随轴前移而加强，不放松**：机器可验的更密（轴 C——改完自己跑通门禁
   再交），机器不可验的按爆炸半径分级 + 边界审计（轴 A 的 L0 清单）。
4. 门 6（EXTERNAL-ACTION GATE）与 D21 外部动作门模型**一字不动**——本决策不放宽任何
   外部动作的确认要求，只把「非外部动作的非阻塞题」从 L2 挪进 L1/L0。

### 4. 轴 B｜收口卡 + 委派完成卡（双形态降级）

**批末收口卡**，四段结构：

1. 本批落了什么；
2. L0 自决清单（供人审计，§2）；
3. 悬而未决（攒下的 L1 题在这里一次问清——L1 的「阶段边界」落点就在这张卡）；
4. D21 待确认（批末 push 等外部动作的确认位，与既有批末 push 流程同位，不新建确认点）。

**委派完成卡**：联动 #177（subagent_oar 一次性委派，完成通知回父会话）——委派任务的
完成聚合在收口卡形态里呈现，不在长跑/委派期间逐条插播（轴 D）。

**双形态降级**：action-cards 服务在运行时缺席或被禁用时，降级为**正文收口段**（batch
组件里的批末收口文本节）——四段结构在两种形态里**同构**（同样的四段，换载体不换内容）。
降级必须显式（S3：降级必声明），不静默。上游机制事实约束实施形态：卡由 kind 的 skill
当回合装载后才可 propose（§背景），故卡形态需要一张随 preset 分发的收口 skill + kind
注册（本插件 `ctx.actionCards.register`）；一回合一卡意味着收口卡**每批末一张**，不逐
 issue 出卡。

### 5. 轴 C 与轴 D 成文

- **轴 C｜机器自检前移**：implement 文本明确「改完自己跑通门禁再交」（文章守则 2）——
  这条纪律本仓已在执行（TEST SCOPE TIERING 节），成文位置并入 wave-1 的正文改写一并
  点名，不另立节。
- **轴 D｜留白与不打扰**：长跑/委派期间完成通知**累积不插播**，判断力集中在 grill
  （文章守则 3/4）；grill 的「只问当前轮能定的问题」既有纪律保持。委派完成通知的呈现
  归 §4 的收口卡/正文段，不新增中断点。

### 6. IRIS 批协议对标采纳面（human 2026-11-06 两条评论，2026-11-07 入册）

IRIS 已运行「10–15 票实施大批 + 5–10 张候选垫队尾 + 批末先 CI 再确认推送」的形态，human
六条对照归置：**①②⑤⑥ 采纳为本决策设计输入，③④ 收敛确认记录在案**。本节是票面评论的
正典化——采纳面的权威归置以 human 评论原句为准，各归其节，防评论随时间流失：

- **①批内不停等（票外发现三分法）→ 轴 A / BATCH MODE 节**：票外发现三分处置——当场能
  解决 → 同族折叠（当前票已毕 + 关联已声明 + 窗口健康三条件，门 5 既有判据）；不阻塞 →
  立票后继续当前票；阻塞 → 立票 + 当前票 WIP 存档 → 跳下一票（整批不停摆）。与 L0/L1/L2
  **互补**：三分法管「票外发现」的处置，L0/L1/L2 管「决策」的分级——两者合起来才覆盖
  批内全部停等诱因。
- **⑥候选垫队 + 积压护栏 → 轴 A / BATCH MODE 节**：批容量 10–15 票 + 候选 5–10 张垫队尾，
  阻塞补位从队尾填补；积压护栏 = **10 张未推票（票数计，同票多 commit 合并计 1）或 3 天 →
  汇报 push checkpoint**；批末红 CI 按 commit 边界二分；票内关票交互（本地门禁链全绿 +
  code-review 双轴过 → 三段式关票）与 enforcer 关票抽查面的交互在 wave-1 判定。
- **修正案（冲突感知三段式跳票协议）→ 轴 A / BATCH MODE 节**：三分法 ③「存档跳过」的
  隐含前提——当前票 WIP 改动面与下一票写域**不相交**——在阻塞场景经常不成立（阻塞常由
  写域冲突引起），三种恶化路径：存档不干净（stash 纠缠 = 变相停摆）、静默携带污染（A 的
  WIP 混进 B 的开工面，批末红 CI 无法按 commit 边界归因）、resume 冲突后置爆（stash pop
  撞上 B 已提交面，爆在批末收口且丢失 A 票现场）。协议四段：
  **存档前判定**（当前票 `git diff` 含 staged 改动面 vs 下一票声明 touch-set；不相交 →
  原路径存档跳；相交 → 分支留档路径）；**分支留档**（`git switch -c wip/<票号>-<slug>` →
  WIP commit 上分支 → 回主线开下一票新分支——#103 一票一分支从「并行会话纪律」升格为
  「批内执行形态」，机制上消灭 WIP 交叉、把冲突推迟到合并边界显式化，而非靠 stash 纪律
  打补丁；批内零 push 不受影响，分支纯本地）；**交接/状态面写全**（分支名、WIP commit、
  冲突点、resume 条件——状态面三件套 + goal 生命周期同步，更新一个 ≠ 其它也更新）；
  **批末 CI 语义不变**（CI 只跑主线已提交面，分支 WIP 不进批末 CI，红 CI 二分不被污染）；
  **resume 显式化**（在分支上继续或 merge 回主线，冲突在分支边界解决，保留 A 票现场；
  禁止「回主线凭记忆重做」）。
- **②批末顺序成文钉死 → 轴 B/D 收口卡顺序语义**：`summary gate 呈现（含 retro 聚合）→
  先跑 CI 至全绿 → 再向 human 确认是否推送 → push`——CI 在确认**之前**跑，human 的确认
  内容 = 「是否推已全绿的结果」，单次决策点零重复确认。实证教训：IRIS 批 Z 末 agent
  倒置为「确认后再跑 CI」被 human 纠正（两次以上勿再犯）→ 顺序必须成文钉死。收口卡
  第 4 段（D21 待确认）即此顺序的卡片化呈现，**不是**「与既有流程同位」的模糊表述。
- **⑤L2 提问规范 → 门 3 L2 补两条**：一次只问一个决策（两票并行逐票串行问）；必须带
  前因后果（背景节：议题由来 / 关键事实 / 各选项实质与成本 / 与既往定案关联）。L1 攒批
  与 L2 立即问的分工不变，L2 的单次提问质量按此补强——与 grill contract 四件套格式
  叠加（一次一题本就是其第一条），不另造提问格式。
- **③④收敛确认（记录在案，无 adoption 需求）**：③ 批内禁跑重 CI——廉价门禁链逐票 +
  重 CI 批末一次，与本仓快集/全量分层（#129）同构，独立收敛，对照在案；④ 交接授权断言
  不构成执行许可——IRIS 批 AA 事故（凭交接一句话预授权直推 13 commit）在本仓 D21 +
  #156/D52 口径（agent 自述不构成授权、逐跳显式确认）已有同款，收敛确认。

总判断（human 原文）：IRIS 的形态与 #179 是同一注意力模型（批内自治 + 机器自检前移 +
批末单次决策点）的两份独立实现。

## 后果与边界

- §6 采纳面入册后，wave-1 的正文改动面 = 门 3（骨架文件）+ BATCH MODE 节（组件文件）
  两处，基线重取一次完成；批协议数值（批容量 10–15 / 候选 5–10 / 护栏 10 票或 3 天）是
  human 提供的 IRIS 运行读数，照抄入正文作起点，后续按本仓批史（#103/#137 族）校准，
  不是硬编码 KPI。
- 门 3 分层后，「立即问」的题量预期下降，但**问题质量门（grill contract）不变**——
  L1 攒批仍走「一次问清」的四件套格式，不是降低问的质量。
- L0 清单审计是**新增的人工审计点**（阶段边界扫一眼）：这是注意力轴的显式交换——
  用低频批量审计换高频逐条中断；若审计发现 L0 滥用，回退手段是收紧（判据加严或该类
  题目降 L1/L2），不是取消分级。
- 收口卡是**可选增强**：服务的运行时激活属环境侧事实，双形态降级保证缺席时四段结构
  仍在（正文形态）——卡形态缺席不构成工作流回归。
- 理论模型（中断 × 装载成本）是**启发式**，不是可测指标；本决策不引入注意力损耗的
  度量装置，L0 清单行数与收口卡四段的填写率是间接观察面，非 KPI。
