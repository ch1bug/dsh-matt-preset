# 检查点同步正反样例集

> 本文件是匿名合成面：不含真实票号（判据出处见 `docs/agents/issue-tracker.md`
> 「检查点同步、处理回执与合并前复核」节，启用前提与授权分层见「协作契约」节；
> 协作契约样例见 `docs/collaboration-contract-examples.md`）。

**匿名合成声明**：全部样例为合成场景，票据一律「票甲 / 票乙 / 票丙」占位——不含任何
私仓票面、业务数据或本机环境信息。判据本体在 `docs/agents/issue-tracker.md`
「检查点同步」节；本文件只供**对照演训**：执行会话照三检查点自测（开工/恢复 → 请求复核
→ 合并前），Spec 复核（`docs/code-review-brief.md` §2 的 5g 条）照「记录面 / 回执
三分类 / 冲突保全 / 合并前核对」逐例核对。样例的语义判断由评审承担，机械守卫
（`tests/verify-checkpoint-sync.mjs`）只钉文本送达与入口在场，不判逐例语义。

**纵向场景**（一条闭环从票在飞走到 PR 待合并复核）：某项目显式启用协作（采用记录在场，
判据同协作契约样例 P2）。两张在飞实现票（票甲、票乙）分属**两个独立工作区**的执行会话，
另有方向重叠的票丙在飞。项目维护者确认了一个新决定并落成**关联 issue 上的可回读记录**：
「模块 X 的对外接口由 A 形态改为 B 形态」，写明授权依据（维护者评论）、影响范围（消费
X 接口的实现）、受影响任务（点名票甲 / 票乙 / 票丙）。此后票甲走到 PR 待合并复核。

## P1 票甲「已采用」（正例：实质影响，改实现并留痕）

- **契约背景**：同纵向场景；项目已启用协作，接口变更属跨模块接口授权（授权分层见协作
  契约节），决定记录三要素（授权依据 / 影响范围 / 受影响任务）齐全。
- **会话读数**：票甲会话在**请求复核检查点**现查决定记录（不凭认领时读过的旧印象），
  发现本票消费 X 接口，实质受影响 → 实现改为 B 形态，AC 措辞的相应调整先取得维护者
  授权（票面留痕，不静默改）→ 回执「**已采用**」写在关联票评论：决定记录指针 + 本票
  改动说明。PR 描述附回执与依据；**合并前核对**：当前提交的验证证据（命令 + 退出码 +
  证据路径落在当前提交上）、最新决定现查、回执齐全、批准 = 一位非作者维护者。
- **判据核对**：三检查点都执行（开工/恢复已回读、请求复核现查、合并前核对）；回执分类
  正确且附依据；AC 调整走了授权，不是静默改。
- **判定**：**合规**。PR 进入「等候合并复核」态——流程检查通过不等于自动合并，放行仍
  走项目批准（协作契约节 PR 验收）。
- **责任归属**：回执真实性由会话承担（复核者对照记录核实）；合并放行由非作者批准给出；
  评审能从 PR 描述直接读到三分类回执与依据，不需要翻聊天记录。

## P2 票乙「经核实不影响」（正例：一句可审计的核实依据）

- **契约背景**：同纵向场景；票乙与票甲在不同工作区并行，票乙动的是模块 Y 的内部实现。
- **会话读数**：票乙会话在同一检查点现查决定记录——受影响任务点名里没有票乙，但会话
  不止看点名，还核实了自己的实现面：本票不改 X 的调用侧 → 回执「**经核实不影响**」
  写进关联票评论，依据一句可审计：「决定改的是 X 接口的消费侧，本票只动 Y 内部，无
  交集」。合并前再现查一次（无新增决定）→ 核对通过。
- **判据核对**：「经核实不影响」有核实动作与范围说明，不是「看了」两字；受影响任务
  点名只是线索，核实以本票实现面为准（点名 ≠ 免核）。
- **判定**：**合规**。并行工作不受拖累——同步契约的目的是让受影响者停下来，不受影响者
  有据继续。
- **责任归属**：核实依据的真实性由会话承担，复核发现「不影响」声明与实现面矛盾时报缺失；
  两个工作区互不等待——没有跨机器实时保证，各自按检查点节奏同步。

## P3 票丙「存在冲突」（正例：先保全，再暂停，沿授权处理）

- **契约背景**：同纵向场景；票丙的实现方向与「接口改为 B 形态」相反（它正在把 X 接口
  往 A′ 形态重构）。
- **会话读数**：票丙会话在检查点发现**方向冲突** → 三步顺序执行：① **checkpoint 保全**
  ——先 WIP commit 到分支、恢复条件写进状态面（不裸 stash）；② **暂停受影响部分**——
  只暂停票丙受接口决定影响的部分，票丙里与 X 无关的子面继续，**不单方面让其他票停工**；
  ③ **沿事项授权处理**——接口授权属维护者分层，向维护者报冲突并请求处置；AC 不静默
  改动。维护者授权「票丙转向 B 形态」留痕后，票丙按新方向续做并回执。
- **判据核对**：冲突回执三要素（冲突点 + 已保全 + 已暂停）齐全；保全在前、暂停在后、
  授权处置收尾，顺序没有跳步；AC 调整有授权留痕。
- **判定**：**合规**。暂停是**局部的**（受影响部分），不是全停；方向处置是**授权的**，
  不是实施者自选出路。
- **责任归属**：保全与暂停由会话执行并留痕；方向取舍由授权人（维护者）给出；评审发现
  「冲突未保全就继续」「全停无关票」「静默改 AC」任一形态即报违规。

## 评审视角（纵向闭环的收口）

PR 待合并复核时，评审能区分两类 PR：**可继续的**（P1 / P2——回执分类明确、依据可审计、
当前提交证据在场）与**缺少处理依据的**（一个 PR 只在描述里写「已知该决定」、没有三分类
回执——按缺回执退回，见 N1 / N2）。合并前的流程核对**不是原子锁**：平台保护未配置时，
它约束的是流程自觉，不声称拦截已发生。

## N1 只发评论不当处理（反例：互动 ≠ 回执）

- **契约背景**：同纵向场景；决定记录发布后通知已送达两票。
- **会话读数**：票甲会话在决定记录下评论「看到了，谢谢」就继续按原方向实现并提交 PR。
- **判据核对**：回执判据——**三选一分类 + 依据**；「看到了」不是三分类之一，评论发送
  成功不构成处理结果。
- **判定**：**违规**。正确形态：照 P1 或 P2 给出分类回执（实质影响 → 已采用；无交集 →
  经核实不影响），只发社交性评论不解除处理义务。
- **责任归属**：复核发现 PR 无三分类回执时按缺回执退回；「通知已送达」不是「已处理」
  （通知只加速发现）。

## N2 回执只有已读（反例：阅读行为冒充处理结果）

- **契约背景**：同纵向场景。
- **会话读数**：票乙会话在票面写「已读该决定」，未分类、未核实，随后提交 PR。
- **判据核对**：**已读不代替回执**——回执是处理结果（已采用 / 经核实不影响 / 存在
  冲突），阅读行为三者都不是。
- **判定**：**违规**。正确形态：核实实现面后给出「经核实不影响」+ 一句可审计依据（P2
  形态），或分类为其他两类。
- **责任归属**：复核对照三分类判据，缺分类即退回；评审不把「表态积极」当「依据可审计」。

## N3 缺授权的「决定」（反例：私人聊天冒充权威记录）

- **契约背景**：同纵向场景；但这次的「接口改 C 形态」只出现在一位协作者的私人聊天消息
  里，没有任何票面 / PR 记录。
- **会话读数**：票丙会话读到聊天内容后当作新权威，直接照做并宣布「已采用新决定」——
  决定本身无授权依据、无可回读记录。
- **判据核对**：记录面判据——**私人聊天 / 本地投影不是新的团队权威库**；「有人说过」
  不是决定记录；授权分层（协作契约节）里接口变更的授权人由项目契约定，聊天者身份不
  推导授权。
- **判定**：**违规**。正确形态：先让有权者把决定落成关联 issue / PR 的可回读记录
  （发文守外部动作门），记录三要素齐全后才进入检查点处理；记录缺席 = 缺项如实呈现并
  暂停相关决定，不照聊天内容实施。
- **责任归属**：会话不得把聊天投影成权威；复核发现「实施依据是聊天记录」时报缺失；
  决定的确认属授权人（gate 3 决策边界同族）。

## N4 复核后新增方向决定只引旧回执（反例：旧回执跨决定复用）

- **契约背景**：同纵向场景；票甲的 PR 已过一轮复核意见，复核完成后维护者又确认了
  一条新方向决定（B 形态再调整为 B′）并落成可回读记录。
- **会话读数**：票甲会话直接引用复核完成时的「已采用（B 形态）」回执合并，对新出现的
  B′ 决定不做重新判断。
- **判据核对**：合并前核对判据——**复核后新增相关决定必须重新判断适用性**并回执，
  旧回执只对它处理的那条决定负责，不能跨决定复用。
- **判定**：**违规**。正确形态：现查新决定 → 重新分类回执（若实质影响 → 再走已采用
  流程；若经核实不影响 → 给出新依据）→ 合并前核对重新过。
- **责任归属**：复核者合并前现查最新决定面，发现「决定时间晚于回执时间且未重新判断」
  即退回；「当时处理过了」不豁免新决定。

## N5 读取失败宣称已同步（反例：读不到 ≠ 已同步）

- **契约背景**：同纵向场景；某检查点上决定记录所在票因权限问题不可达（读取失败）。
- **会话读数**：票乙会话读取失败后，在 PR 描述写「决定面已同步，本票不受影响」——实际
  上决定内容根本没读到。
- **判据核对**：**读取失败不宣称已同步**——读不到时如实报失败并停在该检查点；「没读到
  异议」与「读到了且核实无交集」是两回事。
- **判定**：**违规**。正确形态：报「决定记录不可达，检查点未完成」，暂停受影响的判断，
  等读取通道恢复或由可读者代理核实后重新过检查点；不静默跳过。
- **责任归属**：读取失败由会话如实上报（loud）；复核发现「同步声明与读取失败同时存在」
  即报缺失；无后台轮询义务不等于可以谎称已同步。

## N6 旧提交测试冒充当前提交证据（反例：证据不落在当前提交）

- **契约背景**：同纵向场景；票甲按 P1 完成回执与实现，合并前又推了一个修正提交。
- **会话读数**：票甲会话在合并前核对时引用**修正提交之前**的旧全绿测试结果当「当前提交
  的验证」，声称证据齐全请求合并。
- **判据核对**：合并前核对判据——**当前提交证据**：验证命令 + 退出码 + 证据路径落在
  **当前提交**上；提交更新后旧证据失效，旧提交的测试结果不能冒充当前提交的证据。
- **判定**：**违规**。正确形态：在当前提交上重跑验证并重取证据，再过合并前核对。
- **责任归属**：证据时效由会话承担；复核对照提交哈希与证据时间，发现「证据早于当前
  提交」即退回；这不是流程洁癖——旧证据与当前提交之间的改动未经验证。

---

**对照速查**：N1 / N2 与 P1 / P2 的分界是**三分类回执 + 可审计依据**——互动与阅读都不
是处理结果。N3 与 P 系的分界是**可回读的授权记录**——聊天不是权威库，记录三要素（授权
依据 / 影响范围 / 受影响任务）齐全才进入处理。N4 的分界是**回执与决定的一一对应**——
复核后新增决定重新判断，旧回执不跨决定复用。N5 的分界是**读取事实**——「读不到」如实
报失败，「没读到异议」不等于「已同步」。N6 的分界是**证据落点**——当前提交上的验证才
算当前提交的证据。
