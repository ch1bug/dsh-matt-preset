@@ main-flow
MINIMAL FLOW — idea → ship:
1. Sharpen — grill only when the shape is genuinely undecided (an open
   decision); /grill-with-docs in a workspace, else /grill-me, keeping
   the `domain-modeling` vocabulary. A decided spec → /to-spec →
   /to-tickets; a decided shape → /implement. In the grill ask only what
   the current round can settle — a question waiting on an in-flight fact
   or an unreported subagent is not this round's.
2. Build. Multi-session → /to-spec → /to-tickets (blockers first) → one ticket
   per fresh session via /implement; single-session → /implement here.
   /implement drives /tdd (red→green), closes with /code-review before the
   commit; a PR body goes through /pr.
3. Retro. /retro changes the ENVIRONMENT, not the code.
@@ minimal-note after=main-flow
MINIMAL PROFILE — the same workflow, compressed: the seven gates below are the
shared text word for word, DONE / TEST SCOPE TIERING / RECOVERY DISCIPLINE keep
their substance, and the rest is cut to essentials. The standard profile has
the full text. Never read terseness as permission to skip a gate.
@@ enforcement-done
DONE — verification includes the remote CI. Per-issue: after a push, confirm
the pushed commit's CI is green; red CI is current-ticket work, never "trivial"
spare work. Batch: per-issue done = local verification + code-review; CI green
is confirmed once, at the batch-end push.
@@ enforcement-tiering
TEST SCOPE TIERING — pick the smallest tier that can prove the change and name
it in the ticket's evidence line: ① the single test file touching the change
(while iterating); ② the module's own suite; ③ the full verify set (+ e2e) at
closure, or when the change touches a high-risk surface (persona / handoff /
enforcer / installer / sandcastle). Declaring a tier CI covered that you
skipped locally is part of the evidence, never a substitute for it.
@@ enforcement-recovery
RECOVERY DISCIPLINE — a resumed or handed-off session treats the state file as
the source of truth, never memory: batch-state.md for the batch,
.scratch/progress.md for the snapshot, the handoff document for its session.
First move = verify the environment snapshot. If the state file is missing,
stale, or contradicts the observed environment, STOP and ask — never guess and
never silently rewrite the record.
@@ batch-mode
BATCH MODE — only when the human declares a batch; never on by default.
- ENTRY CONTRACT: RFA = no user in the loop AND no open decision; five things
  pinned in the body (write scope, criterion form, acceptance reading, closing
  rule, push checkpoint) — else RFH. A real decision found mid-work (exclusive
  ACs, a destructive step, an out-of-scope write) downgrades to RFH and stops;
  everything else is routine: decide, and record "decided X because Y".
- CONFLICT ZERO before labelling RFA: ACs consistent; the symptom re-measured
  on HEAD; the docs the ticket cites read (`git grep`) and judged still-true or
  superseded; duplicates / dependency direction / batch overlap checked. No
  wording that pushes a decision forward, and no line admitting the ticket still
  needs a human decision (list: `docs/agents/issue-tracker.md`; run the repo's
  matcher when it ships one).
- PRE-AUTHORIZATION LIST (what a declaration licenses): the write scope; create
  tickets (never close in-batch, read the labels back — one category + one
  state); closing per the mode chosen at declaration (default: per-ticket
  confirm; undeclared → loud line), never outside the declared members; one
  push at the batch end.
- STYLE PREFERENCE (#49): out-of-batch Bucket-B confirmation timing rides the
  user file <DSH_HOME>/batch-style-preference.md (shape: docs/batch-state.md).
  No file → 保守 (default, everything as declared); 标准 = 保守 + tickets in
  the batch state's 批外票清单 may be re-labelled and closed unconfirmed
  (three evidence elements; registration is the human's call — the agent
  never registers). Two tiers only, neither includes push; the
  preference changes WHEN confirmation happens, never the action's nature.
  HUMAN-write-only: transcribe verbatim what the human approved, echo it back
  with the absolute path, then read-only; ask ONCE at the first declaration
  with no file on record.
- CLOSE-OUT STEP before declaring: classify the backlog, merge same-family
  tickets, drop done-but-unclosed tickets from the ready count, record it.
- Batch = the issues the human names, plus the end point. Inside a batch: each
  ticket → local commit + local verification + code-review → NO per-ticket
  push; the remote CI is confirmed once, at the batch-end push.
- ONE TICKET PER SESSION still holds: every ticket gets its own /implement
  session, handing off through .scratch/batch-state.md (members, end point,
  progress, unpushed commits). Never chain tickets in one session.
- AUTO-HANDOFF: when a ticket closes locally and batch-state.md names a
  successor, hand off to it (fresh + directed, `implement` declared) instead of
  waiting to be told. Exceptions: a needed human decision, a requested pause,
  or the end point → go to the wrap.
- Batch end: full-issue summary (A/B/C, created and updated) → human
  confirmation → one push → all-green CI; never pre-authorized. Only declared
  members: at 5 unpushed tickets or 1 week, pause for a push checkpoint.
- AUTONOMY DIGEST (#49): the wrap conclusion carries one line per autonomous
  action outside the declared authorization — 自主 <动作> · #<票号> ·
  commit <sha> · 证据: <命令> → exit <code> · <输出路径>; in-batch actions
  stay as Progress-row pointers (not re-copied); a line missing evidence is
  marked 未验证 and escalated (D47); a separate ⚠ 无授权依据的动作 section
  lists unauthorized moves.
- ISSUE DISCIPLINE: every discovery lands in the tracker, is processed, then
  the issue is updated with the fix and its evidence. Bucket A (blocks
  verification) pauses the batch for the human; B and C continue.
- SANDBOX BATCH MODE (opt-in): the main session orchestrates, sandboxed workers
  execute; audit each ticket before launch, and every launch is an
  external-action-gate event.
@@ text-pushes-exclude-actions
TEXT PUSHES EXCLUDE ACTIONS — a text/docs-only push must not trigger CI: keep
paths-ignore for those paths in ci.yml.
@@ context-hygiene
CONTEXT HYGIENE — judge window health by BEHAVIORAL SIGNALS (repeated
re-reads, circling, gate violations, shrinking replies, decision drift), never
by cache-read %: reuse is a COST metric, and a long context still attends its
full history. At every phase boundary decide in order: Continue (default) →
Subagent → /compact → /handoff. You cannot switch the main session yourself:
write the artifact, create the child, then STOP and tell the human to switch.
As the CHILD of a handoff: a "## 本会话任务（human 已定向）" section means an
assignment (verify the snapshot, restate, DECLARE START); without it, verify,
restate, and ASK. A snapshot mismatch stops you: report before starting.
@@ methodology
METHODOLOGY — frontier (ask only what is unblocked — never a question waiting
on an in-flight fact or an unreported subagent; facts are yours, decisions are
the human's) · red loop (red before green, one slice) · tight loop (one
command that goes red on THIS bug) · tracer bullets (vertical slices, blockers
first) · primary sources · deep modules (much behaviour behind a small
interface) · domain language (CONTEXT.md, ADRs) · human is the index.
@@ human-communication
HUMAN COMMUNICATION — never assume the human has the background: 2–3
sentences of causal chain before a question or decision, and one line of
context per cross-session pointer. A `/wait-what` or a follow-up is the
signal that density was too high — name the assumption, restate, sediment.
