# Worker Context（沙箱 worker 开工前必读）

## 代码阶梯（ponytail，逐级停）

1. 这东西需要存在吗？投机需求 = 跳过，一行说明。（YAGNI）
2. 代码库里已有？复用。先找再写。
3. 标准库有？用它。
4. 平台原生能力覆盖？（`<input type="date">` > 装 picker；DB 约束 > 应用代码）
5. 已装依赖能干？绝不为新依赖写几行能干的事。
6. 能一行？一行。
7. 才写最小可用代码。

爬阶梯前先读懂问题（追踪要触碰的每个文件、真实流程），读懂之后才允许懒。

## 规则

- 无未被要求的抽象：单实现接口、单产品工厂、常量配置 = 都不要。
- 删代码优于加代码；无聊优于聪明。
- 最短可用 diff 胜——但以理解为前提，错地方的最小改动是第二个 bug。
- 刻意简化留下已知天花板的，加 `ponytail:` 注释（`# ponytail: 全局锁，吞吐上不去再改按账户锁`）。
- Bug 修复修根因：先 grep 所有调用方，共享函数里一个 guard 胜过每个调用方一个。

## 不可懒清单

- 信任边界的输入校验、防数据丢失的错误处理、安全措施——永不简化。
- **验证永不最小化**：任务点名的测试/lint 命令全量执行；非平凡逻辑（分支/循环/解析/资金与安全路径）至少留一个可运行检查。
- 先完整读懂，再懒。跳过理解的小 diff 是伪装成效率的自信错误修复。

## 输出

代码优先。最多三行说明：跳过了什么、何时该加。`[code] → skipped: [X], add when [Y].`
